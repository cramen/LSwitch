# Особенности macOS API, проверенные в LSwitch

Наблюдения из спайков и живого тестирования (этапы 0–2). Всё ниже —
проверенное поведение на macOS 14.5 (arm64), а не документация Apple.

## TCC (разрешения)

- `CGEvent.tapCreate` **успешно создаёт tap без разрешения Input Monitoring** —
  события просто не доходят. Молчаливый отказ: проверяй доставку, а не создание.
- Запуск голого бинарника из терминала наследует TCC-контекст терминала:
  `CGPreflightListenEventAccess()` возвращает `true` (разрешение Terminal),
  но tap всё равно молчит. Реальная проверка — только `.app`-бандл через `open`.
- Разрешения привязаны к designated requirement подписи: ad-hoc (cdhash) —
  сбрасываются при каждой пересборке; стабильный сертификат — переживают
  (см. `docs/dev-setup.md`).
- macOS 14.5: session-level listen-only tap, запущенный через `open`,
  получает события, **даже когда приложения нет в списке** «Мониторинг ввода»
  (наблюдено; полагаться на это в релизе не стоит — см. R5 в TZ.md).
- `tccutil reset <service> <bundle-id>` — рабочий способ переоткрыть диалоги.

## Многопоточность (главный поток обязателен)

- **TIS API** (`TISCopyCurrentKeyboardLayoutInputSource`, `TISSelectInputSource`):
  вызов вне главного потока = `EXC_BREAKPOINT` через `_dispatch_assert_queue_fail`
  в HIToolbox. Не просто «не рекомендуется» — процесс убивается.
- **NSWorkspace.frontmostApplication** — тоже только главный поток. Оркестратор
  читает его на MainActor; `didActivateApplicationNotification` сбрасывает контекст ввода.
- NSPasteboard и AX IPC из фона работают (наблюдено).

## Accessibility API

- Electron-приложения (Obsidian, VS Code, Slack, Discord — детект по
  `Contents/Frameworks/Electron Framework.framework`): `AXUIElementSetAttributeValue`
  на `AXSelectedText` возвращает **success, но вставляет текст у курсора вместо
  замены диапазона**. После AX-записи слова обязательна верификация чтением
  `AXValue`; для Electron — сразу clipboard-режим, без AX-попыток.
- AX-позиции — в UTF-16 units; переводить через `NSRange(_, in:)`.
- Secure-поля: subrole `AXSecureTextField`.
- Safari/WebKit также может подтвердить `AXSelectedText`, не выполнив замену.
  Попытка записи способна рассогласовать DOM-выделение и AX-диапазон, поэтому
  Safari сразу использует clipboard-профиль. Нативные текстовые поля и HTML
  contenteditable необходимо проверять отдельно.
- После AX-записи каретка не обязательно схлопнута: TextEdit оставлял её до
  разделителя, GIGA IDE — выделял исправленное слово. Конечный диапазон нужно
  устанавливать явно и проверять вместе с фактическим текстом.
- Парольный запрет нельзя превращать в обычный AX-отказ с clipboard-fallback.
  Проверяются также `IsSecureEventInputEnabled` и `AXProtectedContent`.

## Симуляция клавиатуры

- Метка собственных событий через `CGEventField.eventSourceUserData`
  (магическое значение) **доезжает** от постинга до callback tap —
  подтверждено косвенно: синтетика не ретриггерит конвертацию.
- Повторный `setIntegerValueField(.eventSourceUserData, ...)` может не изменить уже
  записанную метку. Проверяется readback; при отказе обновляются `CGEventSource.userData`
  и источник события. Тесты покрывают перезапись, копирование и сериализацию события.
- `CGEvent.data` → восстановление CGEvent может обнулить userData. Очередь LSwitch
  сохраняет копии событий без сериализации; служебное событие после десериализации
  требует повторной маркировки и проверки результата.
- `Cmd+C` без выделения в CodeMirror-редакторах (Obsidian, VS Code)
  **копирует всю строку**, а не «ничего» — слепое копирование приводило
  к дублированию текста.
- ⌥⇧← (выделение слова) подчиняется гранулярности приложения и режет слова
  по пунктуации («rf;tncz» → «tncz»). Надёжнее точное ⇧←×N с последующей
  сверкой скопированного с ожидаемым словом.
- Паузы: после клика по меню статус-бара нужно ~150 мс до возврата фокуса
  в приложение перед Cmd+C; после Cmd+V — ~150 мс до восстановления буфера,
  иначе вставится старое содержимое.
- Для Copy/Paste надёжнее нативные команды меню активного приложения: они
  определяются через AX по `AXMenuItemCmdChar` и modifiers=0 (Command), без
  открытия меню. Команды кэшируются по PID и повторно проверяются перед вызовом.
  При подтверждённой вставке чтением текста ждать фиксированные 150 мс не нужно.
- Резервные клавиатурные команды отправляются в подтверждённый PID, с отдельными
  событиями модификатора и интервалами. Ожидание должно освобождать главный
  run loop: синхронный sleep задерживает также собственный event tap.
- AX IPC в Electron может допустить обработку нового ввода между выделением и Paste.
  Для секции замены используется активный session tap с коротким удержанием ввода,
  освобождаемым после результата и TIS. Один лишь последовательный Swift-код эту гонку не устраняет.
- Уже ожидавшая клавиша может содержать Unicode прежней раскладки после TIS-переключения.
  Коррекция ограничена временем операции и обычными keyDown; команды не меняются.
- При автоматизации тестов нужно подтвердить фактический foreground-процесс.
  Управление фоновым окном не воспроизводит глобальную обработку LSwitch.

## Раскладочная пунктуация

Символы с маппингом в раскладке (`;`→ж, `'`→э, `,`→б, `.`→ю, `` ` ``→ё …)
обрабатываются единообразно (design D6, stage2): часть слова при извлечении,
триггер автоконвертации, хвостовая пунктуация обрезается.

## Открытые вопросы

- Приложения с ленивым чтением буфера (pasteboard promises): принимают ли
  восстановленный снимок — не проверено (open question спайка P0.3).
- Долгосрочная стабильность tap (8 часов, sleep/wake) — код восстановления
  есть, длительный прогон не проводился.
