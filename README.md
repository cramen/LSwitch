# LSwitch

Нативное macOS-приложение для исправления текста, набранного в неправильной
раскладке клавиатуры (`ghbdtn` → `привет`). Открытая замена Punto Switcher для Mac.

**Статус на 2026-10-15:** ручная конвертация и словарная автоматика реализованы,
но **приёмка этапов 0, 1 и 2 ещё не завершена**. Исправления сохранности текста,
точного undo и защищённых полей приняты в своём объёме и
[архивированы](openspec/changes/archive/2026-10-14-fix-conversion-safety/notes.md).
Это не закрывает полную матрицу совместимости или подготовку релиза.

Последние общие локальные `make build` / `make test` / `make app` (2026-10-15, 12:44 МСК):
**417 тестов, 0 ошибок, 0 пропусков**, включая защиту кодового контекста и строкового кандидата.
Длительное наблюдение относится к прежнему бинарнику на 322 тестах;
новые сборки не наследуют его результаты. Полная живая приёмка кодовой защиты открыта.
[Последний опубликованный CI, `3a28be9`](https://github.com/cramen/LSwitch/actions/runs/38639631742)
относится к прежним 255 тестам; CI новых изменений ещё не пройден.
[Точные сборки, измерения и остаток проверок](docs/acceptance-2026-10-15.md).

## Что проверено и что остаётся

- В отдельных тестовых документах TextEdit, Safari, Obsidian и GIGA IDE
  проверены перечисленные в архивном протоколе конвертации ru/en, продолжение
  ввода, точный undo и отсутствие потери слова. Не каждый сценарий проверен
  во всех четырёх приложениях. Первые быстрые сценарии Obsidian и Safari после
  запуска могут безопасно отказаться от исправления, сохранив введённый текст.
  Прогретые Safari textarea/contenteditable и password-поле повторно проверены.
  В новом прогоне исправлены блокировка главного потока первым звуком и отложенное
  выделение Chrome; первый быстрый Safari-сценарий со звуком прошёл за 184,243 мс.
  Безопасный отказ не считается успешным исправлением.
- На живой системе проверены окно настроек, OFF → ON, отзыв/возврат Accessibility
  и сохранение общего OFF при возврате разрешения. Проверены обычная регистрация
  и снятие Login Item, изменение/истечение окна undo при 1/3 с, обучение после
  двух отмен и после одной при пороге 1, обновление открытого списка и ручные add/remove.
  После исправления собственного звукового ID пользователь подтвердил слышимый ON
  и исчезновение звука в последовательной проверке ON → OFF.
  [Протокол MVP](openspec/changes/stage1-mvp/notes.md),
  [протокол автоматики](openspec/changes/stage2-autoswitch/notes.md).
- Остаются независимый отзыв/возврат Input Monitoring, реальные pending/error
  Login Item и запуск после входа, живые Terminal/iTerm.
  Пользователь выбрал защиту кодовых конструкций с сохранением автокоррекции
  комментариев и строк. На 379 в TextEdit код сохранён, комментарий исправлен,
  ручная команда доступна; найденный строковый отказ исправлен и повторно принят
  на 393: `let message = "ghbdtn ` → `let message = "привет `.
  Полный кодовый снимок пока подтверждает адаптер TextEdit; виртуализированные
  редакторы без такого подтверждения безопасно отказываются от автоматики.
- Конкретный бинарник проработал с активным tap более восьми часов: 240 событий,
  максимум callback 0,873 мс, восстановлений не потребовалось. Это небольшой
  объём ввода; затем пользователь подтвердил физический ввод «привет мир».
  Sleep/wake, смена сессии и переподключение остаются открытыми; внешней клавиатуры нет.
  В следующей сборке на 371 тесте записаны два callback >1 мс, максимум 4,749 мс:
  целевая длительность hot path для нового кода не принята.
  Измерены первые и повторные конвертации от события-разделителя: Chrome
  270,329 / 211,145 мс на 322 и 318,850 мс на 379 превышают цель ≤200 мс.
  Следующая попытка 379 безопасно отказала по timeout захвата clipboard.
  После исправления ожидания helper на 417 обычный Chrome Paste ещё дал отказ;
  последующие ручные попытки на диагностической и нейтральной страницах прошли.
  Причина нестабильности не признана устранённой; ручные 316,830 мс не принимают
  цель автоматики. Бюджет допуска к мутации 400 мс не является метрикой задержки.
- В Chrome подтверждены конкретные RU→EN и EN→RU clipboard-сценарии с нативным
  Unicode клавиатурных команд и сохранённым hash clipboard. В VS Code прошёл
  отдельный EN→RU сценарий в TXT. По делегированному пользователем решению 15 октября
  прежний исследовательский AX ≥3/5 заменён рабочим безопасным механизмом в каждом
  из TextEdit/Safari/Chrome/Telegram/VS Code; старый AX-порог не объявляется пройденным.
  Полная матрица с точными текстом/кареткой/undo/fingerprint, цель ≤200 мс, полная
  clipboard-матрица TextEdit/Chrome и резервный Cmd+C/V RU/EN остаются открытыми.
- Unit round-trip файловых URL не является проверкой всех реальных clipboard
  providers. В живом прогоне после конвертации сохранены исходные hashes RTF/PNG/файлов;
  TextEdit принял текст с жирным оформлением, Preview — PNG 2×2, Finder — два файла
  с точными исходными bytes. Полная матрица, гонка нового копирования и ленивые
  providers ещё открыты. Для неподдержанных file promises согласован явный отказ
  до изменения текста, выделения и clipboard с сохранением исходного provider;
  его дальнейший приём настоящим receiver тоже требуется подтвердить.
  Настоящий modern promise успешно принят исходным receiver, но точный raw replay
  не дал callback за 20 с ни при живом owner, ни после его освобождения;
  равенство bytes само по себе не подтверждает восстановление этого протокола.

## Качество классификатора

Новый размеченный корпус содержит **141 запись и 1029 токенов**:
101 предложение RU/EN, 20 смешанных предложений и 20 строк кода.

| Набор | Accuracy | Ложные срабатывания среди корректных токенов |
|---|---:|---:|
| Весь корпус | 99,51% (1024/1029) | 0,21% (2/939) |
| Поднабор кода | 97,65% (83/85) | 2,35% (2/85) |

Recall ошибочной раскладки — 96,67% (87/90). Общий порог FP ≤1% выполнен
на этом наборе, но в коде он превышен. Это не оценка ошибок за рабочий день
и не результат на 1000 предложениях. Автоматика **по умолчанию выключена**.
[Методика, состав и несовпадения](openspec/changes/stage2-autoswitch/notes.md).

## Принципы

- 🍎 Swift, AppKit/SwiftUI, macOS 13+; живая проверка выполнена на Apple Silicon.
  Universal binary для Apple Silicon и Intel остаётся требованием релизной поставки.
- 🔒 Без телеметрии и сетевых запросов; история нажатий не записывается на диск.
- 📋 AX-путь не меняет clipboard; clipboard-путь восстанавливает собственный
  снимок, сохраняя более новое копирование пользователя. Границы providers указаны выше.
- 🎯 Встроенные профили совместимости Safari/Chrome/Electron и исключения приложений;
  пользовательские per-app настройки автоматики/хоткеев ещё в дорожной карте.
- 📖 Открытый код (MIT); словари — OpenSubtitles CC-BY-SA (см. [NOTICE.md](NOTICE.md)).
- 🛠 Работа через OpenSpec: активные изменения — `openspec/changes/`,
  архивированные изменения — `openspec/changes/archive/`, опубликованные требования — `openspec/specs/`.

Техническое задание и план: [TZ.md](TZ.md).

## Сборка и запуск

```bash
make build      # сборка через полный Xcode; xcode-select остаётся на CLT
make test       # unit- и доступные интеграционные тесты
make app        # .app-бандл со стабильной dev-подписью (.build/LSwitch.app)
make run-app    # сборка + запуск menu-bar агента
```

Для работы нужны Accessibility и Input Monitoring. Подробнее про подпись,
TCC и диагностику (`lswitch --probe`, логи): [docs/dev-setup.md](docs/dev-setup.md),
особенности macOS API: [docs/macos-quirks.md](docs/macos-quirks.md).
Принят [ADR-001](docs/adr/ADR-001-app-sandbox.md): без App Sandbox, вне Mac App Store.
Текущая подпись «LSwitch Dev» обеспечивает локальную разработку;
Developer ID, notarization и релизный дистрибутив ещё не приняты.
