# Техническое задание и план реализации LSwitch

**Версия:** 1.0 · **Дата сверки:** 2026-10-15 · **Статус:** этапы 0–2 реализованы частично; приёмка не завершена

---

## 1. Общие сведения

### 1.1. Назначение

LSwitch — нативное macOS-приложение для автоматического и ручного исправления текста, набранного в неправильной раскладке клавиатуры (`ghbdtn` → `привет`). Позиционируется как современная замена Punto Switcher для macOS, лишённая его ключевых недостатков.

### 1.2. Целевая аудитория

Пользователи macOS, работающие с двумя и более раскладками (первично: русская + английская), — разработчики, писатели, офисные пользователи.

### 1.3. Конкурентные преимущества (ответ на проблемы Punto Switcher)

| Проблема Punto | Решение в LSwitch |
|---|---|
| Заброшенная macOS-версия, нет Apple Silicon | Нативный Swift, universal binary (arm64 + x86_64) |
| Закрытый код, телеметрия, Uninstall Reporter | Открытый код (MIT), ноль сетевых запросов, ноль телеметрии |
| Затирает буфер обмена при конвертации | Сохранение и восстановление буфера; где возможно — работа без буфера через Accessibility API |
| Ложные срабатывания | Настраиваемые эвристики, профили per-app, обучаемый список исключений-слов |
| Не работает в терминалах, Adobe, Excel | Явный per-app whitelist/blacklist, автодетект проблемных приложений |
| Молчаливые отказы из-за разрешений | Онбординг разрешений + мониторинг их сброса после обновлений |
| Только ru/en, жёстко зашито | Архитектура под произвольные пары раскладок (MVP: ru/en) |

## 2. Функциональные требования

### 2.1. MVP (релиз 0.1)

- **F1. Перехват клавиатуры.** Глобальный `CGEventTap` на уровне сессии. Вне временного окна конвертации события проходят без изменений. Удержание начинается до снимков и поиска меню; события доставляются в исходном порядке после завершения операции и cleanup. Unicode ожидавших клавиш изменяется только в окне подтверждённой смены раскладки. Отмена запрещает новые мутации, безопасно убирает узнаваемое собственное выделение и затем освобождает ввод. Уточнение исходного пассивного режима обосновано воспроизведённой потерей текста в `openspec/changes/archive/2026-10-14-fix-conversion-safety/design.md`.
- **F2. Ручная конвертация по хоткею.** Пользователь набирает слово/фразу, нажимает хоткей (по умолчанию: двойной Shift) — последнее слово или выделенный текст конвертируется в другую раскладку, системная раскладка переключается следом.
- **F3. Ручное переключение раскладки.** Хоткей (по умолчанию: одиночный Shift-клик настраиваемый / Ctrl+Space) переключает системную раскладку без конвертации.
- **F4. Откат.** Повторное нажатие хоткея в течение N секунд (по умолчанию 3 с) возвращает сохранённые оригинал, фактический хвост и прежнюю раскладку. Повторный `invert` не является undo; изменившийся контекст/текст запрещает восстановление старого оригинала.
- **F5. Menu bar приложение.** Иконка в строке меню: включение/выключение, текущая раскладка, доступ к настройкам, выход. Без Dock-иконки (`LSUIElement = true`).
- **F6. Настройки.** Окно настроек: выбор хоткеев, включение автозапуска (Login Item через `SMAppService`), звуковое уведомление при конвертации (вкл/выкл).
- **F7. Сохранение буфера обмена.** Все исходные items/типы обычных текста, RTF, PNG и файлов сохраняются и восстанавливаются, пока clipboard принадлежит операции; более новое копирование пользователя не затирается. Реальные получатели и материализуемые ленивые providers обязательны в живой приёмке. Для неподдержанных file promises допускается явный отказ до изменения текста, выделения и clipboard с сохранением исходного owner/provider и подтверждённым приёмом исходного promise после отказа. Граница согласована через делегированное пользователем решение 15.10.2026; raw replay или fileURL не считаются восстановлением promise.
- **F8. Защита полей паролей.** Перехват и конвертация отключаются в secure-полях (детект через `AXUIElement` атрибут `AXSecureTextField` / флаг события).
- **F9. Список исключений приложений.** Пользователь добавляет приложения (по bundle ID), в которых LSwitch не активен. Предустановленный blacklist: Terminal.app, iTerm2, игры.

Текущие границы F3/F5/F6/F9: отдельный настраиваемый хоткей переключения и показ
текущей раскладки в menu bar ещё не реализованы полностью; двойной Shift фиксирован.
Встроенный blacklist содержит Terminal/iTerm2, остальные исключения задаёт пользователь;
общего предустановленного списка игр пока нет. Обычные register/unregister Login Item
проверены в живом UI; системные pending/error и фактический login ещё не приняты.
Отзыв/возврат Accessibility и сохранение общего OFF проверены; независимый сценарий
Input Monitoring остаётся открытым. Окно undo 1/3 с проверено внутри и после срока.
[Протокол MVP](openspec/changes/stage1-mvp/notes.md).

### 2.2. Релиз 0.2 — автопереключение

- **F10. Автоопределение неправильной раскладки.** Анализ набранного слова по частотному словарю / n-граммной модели: если слово типично для другой раскладки и нетипично для текущей — автоматическая конвертация после разделителя (пробел, знак препинания) + переключение раскладки.
- **F11. Эвристики защиты от ложных срабатываний:**
  - не конвертировать слова короче 3 символов;
  - не конвертировать при смешанном регистре/цифрах (пароль-подобные строки);
  - не конвертировать после нажатия курсорных клавиш, мыши (пользователь редактирует, а не печатает);
  - не конвертировать аббревиатуры из словаря-исключений;
  - защищать кодовые конструкции в кодовых документах, сохраняя автокоррекцию
    в подтверждённых комментариях и строках; ручной двойной Shift доступен
    независимо от автоматической защиты;
  - «слово сказало нет»: если пользователь отменил конвертацию этого слова K раз (по умолчанию 2), оно добавляется в персональный словарь-исключений.
- **F12. Персональный словарь.** Просмотр и редактирование слов-исключений, импорт/экспорт.

В текущей реализации F10 использует бинарное словарное правило без n-грамм;
автоматика по умолчанию выключена. Для F11/F12 реализованы модель исключений,
настраиваемый порог и редактор; живой путь двух отмен, порог 1, открытый список
и ручные add/remove подтверждены без перезапуска. Импорт/экспорт не реализован.
Политика кодового контекста выбрана пользователем 15.10.2026; реализация и unit-проверки
входят в набор 513. В TextEdit приняты код, комментарий, ручной обход; строковая
регрессия 379 исправлена и повторно принята на 393. Полная живая матрица остаётся
открытой. Полный снимок кодового документа
пока подтверждает адаптер TextEdit; виртуализированный editor без подтверждения
начала полного документа безопасно отказывает. Метрики исходного лексического корпуса не меняются от выбора
runtime-политики; границы корпуса — в 6.1.
[Протокол автоматики](openspec/changes/stage2-autoswitch/notes.md).

### 2.3. Релиз 0.3 — продвинутые функции

- **F13. Профили per-app.** Для каждого приложения: автоматика вкл/выкл, свои хоткеи, режим (конвертация слова / всей строки).
- **F14. Конвертация выделенного текста.** Хоткей конвертирует произвольный выделенный фрагмент (не только последнее слово), включая смену регистра (ВЕРХНИЙ/нижний/Заглавный).
- **F15. Автозамена (сниппеты).** Пользовательские правила вида `с ув` → `с уважением,`.
- **F16. Диагностика.** Встроенный лог-просмотрщик (локальный, без отправки), кнопка «сбросить разрешения» (`tccutil reset`), экспорт диагностического отчёта.

Встроенный выбор AX/clipboard для Safari/Electron уже существует, но не заменяет
пользовательские профили F13. Простая ручная конвертация существующего выделения
уже работает; смена регистра и остальные расширения F14 остаются в плане.

### 2.4. Out of scope (осознанно не делаем в v1)

- Ведение «дневника» набранного текста (риск приватности, низкая ценность).
- Поиск в интернете из любой программы.
- Windows/Linux-версии.
- Синхронизация настроек между устройствами.

## 3. Нефункциональные требования

### 3.1. Платформа

- macOS 13 Ventura и новее (покрывает все поддерживаемые Apple Silicon и актуальные Intel).
- Swift 6, SwiftUI (настройки) + AppKit (menu bar, event tap), минимум зависимостей. Единственная допустимая зависимость — Sparkle 2 (автообновления), интегрируется с релиза 0.3.
- Universal binary (arm64 + x86_64).

Фактически проект использует `swift-tools-version: 5.10`; строгая миграция
на Swift 6 concurrency не завершена. Живая проверка проведена на Apple Silicon;
универсальная релизная сборка и Intel-приёмка ещё не подтверждены.

### 3.2. Производительность

- Обработка события клавиатуры ≤ 1 мс в hot path (без аллокаций и I/O в callback CGEventTap — события передаются в отдельную очередь).
- Автоконвертация слова ≤ 200 мс от нажатия разделителя.
- Потребление памяти в idle ≤ 50 МБ; CPU в idle ~0%.
- Энергия: приложение не должно появляться в «Using significant energy» (Activity Monitor).

Это целевые критерии. Текущий callback использует замки и копии CGEvent;
соответствие условию без аллокаций не подтверждено. Доступны агрегированные
измерения 240 callback за более чем 8 часов (максимум 0,873125 мс) и CPU/RSS-выборки
только последнего получаса конкретного бинарника 322. Последующий физический ввод
подтверждён пользователем; lifecycle ещё не принят. У следующего бинарника 371
два callback >1 мс, максимум 4,749458 мс, поэтому общий hot path не принят.
Короткая серия 513 (17:25:53 МСК, uptime 659,870 с) дала 289 callback,
два превышения 1 мс, max 3,224292 мс; tapEnabled=true не принимает hot path или 8 часов.
В первом быстром Safari-сценарии измерено 184,243 мс; Chrome показал 270,329 мс
первым и 211,145 мс повторным запросом на 322, 318,850 мс первым на 379 — выше цели.
DEBUG Unicode в Chrome 467–489 дал успешные автоматические замены за 289–337 мс,
включая конкретные продолжение/receipt undo; первый 489 —291,461 мс. Цель не выполнена.
Счётчики guards (470:215/59/11, 489:149/42/10 вызовов isCurrent/documentIdentity/snapshot)
показывают сокращение работы, а не выполнение latency-критерия.
[Условия и происхождение измерений](docs/acceptance-2026-10-15.md).
Бюджет допуска к мутации 400 мс/256 событий отменяет
продолжение записи; он не является гарантией задержки или жёсткой ёмкостью очереди.
Сохранённые события остаются до cleanup/end и не отбрасываются по достижении порога.

### 3.3. Приватность и безопасность

- Ноль сетевых запросов (исключение: Sparkle appcast по HTTPS, только с релиза 0.3 и только проверка обновлений).
- Набранный текст не сохраняется на диск и не покидает процесс (буфер последних символов только в памяти, ≤ 256 символов).
- Код подписан Developer ID + notarization (без этого Gatekeeper и TCC сделают приложение неюзабельным).
- Hardened Runtime с минимумом entitlements: `com.apple.security.automation.apple-events` только если потребуется. ADR-001 уже принят: без App Sandbox, распространение вне MAS. Текущий `.app` подписывается локальным сертификатом «LSwitch Dev»; Developer ID, notarization и Hardened Runtime для релизной поставки ещё не приняты.

### 3.4. Надёжность

- Приложение не должно падать и терять перехват при смене фокуса, sleep/wake, подключении внешней клавиатуры, Fast User Switching.
- Автоматический перезапуск event tap при его отключении системой (`kCGEventTapDisabledByTimeout`, `kCGEventTapDisabledByUserInput`).
- Мониторинг разрешений: при потере Accessibility/Input Monitoring (сброс TCC после обновления) — уведомление пользователю и мастер повторной выдачи.

### 3.5. Качество кода

- Открытый репозиторий, лицензия MIT.
- Линтер SwiftLint, форматирование swift-format, CI (GitHub Actions): сборка + unit-тесты на каждый PR.
- Покрытие unit-тестами: словарь/классификатор, таблицы конвертации раскладок, эвристики — ≥ 80% (UI и event tap — ручное/интеграционное тестирование).

Количество пройденных тестов не является измерением coverage; достижение 80%
требует отдельного отчёта и этим статусом не подтверждается.

| Симуляция нажатий | `CGEvent.post`, `CGEventSource` с флагом-меткой (чтобы не ловить собственные события) |

### 4.3. Конвертация: два режима (ключевое архитектурное решение)

1. **AX-режим:** полный снимок текста и UTF-16-диапазона, проверка доступности,
   прямая замена с подтверждением итогового текста и каретки. Clipboard не меняется.
2. **Clipboard-режим:** при достоверном AX-снимке исходник читается без Copy,
   clipboard готовится до выделения. Устанавливается только AX-диапазон,
   проверяется его устойчивое фактическое состояние, затем вызывается Paste и
   подтверждается результат. Ручная команда сохраняет резервное Copy; его
   повторы ограничены тремя и не расширяют выделение. Без проверяемого снимка
   автоматика отказывается до выделения.

Safari, Chrome и обнаруженные Electron-приложения используют clipboard сразу. Chrome
заранее выбирает клавиатурные команды с нативным Unicode текущей раскладки;
неоднозначный AXPress не повторяется клавиатурной вставкой. Для
остальных AX → clipboard fallback допускается только после доказанно безопасного
отказа с неизменным текстом и восстановленным выделением. Неоднозначная запись
не повторяется другим способом. Режим кэшируется после успеха на текущую сессию.
Нативное меню и клавиатурный Cmd+C/V — разные транспорты: живые успехи первого
не закрывают проверку второго в RU/EN.

Состояние оркестратора и обращения к TIS/NSWorkspace находятся на MainActor.
Удержание начинается до подготовки операции. После отмены отдельный cleanup-grant
разрешает только восстановление узнаваемого собственного диапазона в прежнем
безопасном контексте; затем очередь выпускается. Точный undo использует original,
а восстановление clipboard проверяет принадлежность по changeCount.

### 4.4. Классификатор (автопереключение)

- Подготовлены частотные словари OpenSubtitles: 48 489 RU и 49 172 EN записей.
  Ресурсы — UTF-8 word lists; текущая структура lookup — `Set<String>`, не бинарный trie/DAC.
- Консервативное правило: исходное слово отсутствует в обоих словарях,
  отображённое присутствует ровно в одном. Применяются эвристики и персональные исключения.
  Вероятностный скоринг и n-граммный fallback из первоначального эскиза не реализованы.
- Всё офлайн, в памяти, без ML-фреймворков. Метрики локального корпуса не заменяют внешнюю бету.

## 8. Критерии приёмки релиза 1.0

1. Ручная конвертация работает во всех приложениях матрицы 6.2 в ≥ 9 из 12 строк.
2. Автопереключение: ≤ 2 ложных срабатывания за день активной работы (замер на бета-группе).
3. Исходные items/типы обычных текста/RTF/PNG/файлов после конвертации восстановлены бит-в-бит, если не появилось более новое пользовательское копирование; при нём сохраняются новые данные. Реальные получатели и ленивые providers входят в проверку. Для неподдержанного promise допустим только явный отказ до text/selection/clipboard mutation с сохранением исходного provider и проверенным приёмом исходных данных после отказа.
4. Ни одного сетевого запроса (проверка Little Snitch / `nettop`).
5. 7 дней непрерывной работы без падений и потери перехвата (включая sleep/wake циклы).
6. Установка и выдача разрешений занимают ≤ 2 минут у нетехнического пользователя (тест на 3 людях).


Эти критерии релиза 1.0 остаются целевыми и не считаются выполненными по локальному
прогону 513 тестов. Перед итоговой оценкой пункта 1 требуется явно зафиксировать
12 отдельных позиций и единицу подсчёта: текущая таблица 6.2 группирует приложения,
а подтверждённые четыре программы не заменяют исходный порог ≥9 из 12.
