## Why

Модельные проверки реального скомпилированного Core подтвердили P1: production
clipboard с AX/native-выделением и DEBUG Unicode могут вернуть failed, оставить
собственное выделение и освободить очередь, после чего следующий ввод затирает
оригинал. Общий контракт завершения должен сохранять уже удержанные события и
безопасно передавать их пользователю, когда восстановление редактора не подтверждено.

## What Changes

- Заменить безусловный replay из defer/deinit явным результатом cleanup и атомарным
  владением очередью. Обычная доставка разрешена только при доказанном безопасном
  состоянии; успешный пользовательский сценарий сохраняет прежнее поведение.
- До первого собственного изменения выделения/текста подготовить и проверить
  аварийный приёмник и защиту перехода к нему. Если готовность не доказана,
  отказаться до мутации. Per-PID quarantine и CGEventTapPostEvent остаются кандидатами,
  пока системная приёмка не подтвердила доставку, фокус и поведение при отказах.
- При неподтверждённом восстановлении передать уже удержанную очередь единственному
  владельцу в RAM. Не отправлять её автоматически в прежнее поле, clipboard, файл
  или payload-журнал. Причина и счётчики видны в собственном recovery-окне;
  содержимое раскрывается только по явному действию пользователя.
- Предоставить собственный RAM-редактор для проекции точного Unicode payload событий.
  Фрагменты не обозначают подтверждённую вставку или конечный текст редактора. Пользователь
  может вручную выделить и скопировать раскрытый текст обычной командой. Программного
  экспорта и автоматического исполнения сохранённых shortcuts/мыши нет; произвольная
  последовательность событий не объявляется восстановленной итоговой строкой.
- Сохранить очередь при OFF и закрытии recovery-окна. OFF прекращает перехват;
  graceful quit с нерешённой recovery-записью требует явного решения. Удаление подтверждается
  пользователем. RAM не переживает crash; дальнейший физический ввод после потери
  контроля/разрешений или принудительного завершения не объявляется защищённым.
- Зафиксировать пределы хранения и допуска без молчаливого вытеснения, потери
  уже удержанных событий или бесконечной глобальной блокировки. Сохранить privacy,
  guards, порядок событий и предел mutation lease 400 мс.

## Capabilities

### New Capabilities

- `input-recovery`: владение удержанным вводом, готовность аварийного приёмника,
  локальное восстановление по выбору пользователя и жизненный цикл очереди в RAM.

### Modified Capabilities

- `safe-conversion`: условный replay по подтверждённому результату, безопасный
  отказ при неизвестном cleanup, судьба уже удержанного ввода при Secure Input,
  OFF и завершении приложения. Изменение касается всех AX/clipboard/Unicode путей.

## Impact

Изменение охватывает результат завершения конвертации, адаптеры трёх движков,
InputEventBuffer/EventTapCore, lifecycle приложения и отдельное recovery-окно.
Компоненты реализуются отдельно от обычного runtime; их локальные тесты и DEBUG
preview не заменяют системные probes и живые проверки отказа с последующим вводом.
Новый системный gate не считается готовым по существованию API или зелёному CI.

Основания: `.build/research-incoherence/production-results.json`,
`ProductionResearch.swift`, `native-recovery-options.md` и D11.P1; трасса воспроизведения
сохранена в design и acceptance-протоколе. Это модели с реальным Core, не live-проверки.
Change не закрывает stage0/1/2 или VS Code bridge и не разрешает включить DEBUG Unicode.
