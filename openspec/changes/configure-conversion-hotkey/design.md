## Context

DoubleShiftDetector работает на RawKeyEvent в AppDelegate, после guards безопасности.
SettingsStore сохраняет настройки в UserDefaults. Сам event tap не выполняет AX/TIS/IO.

## Goals / Non-Goals

Goals: сохраняемый хоткей, единый путь conversion/undo, системная проверка регистрации.
Non-Goals: произвольные последовательности клавиш, modifier-only кроме двойного Shift,
автоматическое обнаружение всех локальных команд редакторов, завершение fix-input-recovery.

## Decisions

- Codable-модель в Core: двойной Shift либо keyCode + нормализованные модификаторы.
  UI явно выбирает физическую клавишу (латинские подписи, одинаковая позиция в RU/EN).
- Настройка через список клавиш и флажки модификаторов, без временного глобального recorder.
  Допустимы Ctrl либо Command; обычная буква и Option-only не перехватываются.
- Carbon RegisterEventHotKey резервирует custom-команду; событие запускает обычный
  RawKeyEvent-путь. Carbon handler лишь поглощает системное уведомление, не запускает
  вторую конвертацию. Регистрация освобождается при остановке tap/OFF.
- Новый registration готовится до удаления старого. Ошибка не меняет сохранённый выбор.
  Если сохранённое сочетание невозможно зарегистрировать при старте, возврат к double Shift
  сопровождается видимой ошибкой. Программные изменения settings повторно валидируются.
- Чистый детектор подавляет повторы до keyUp; synthetic игнорируется. Custom matched keyDown
  не проходит в classifier и не очищает буфер ожидаемого слова. Reset сохраняет latch
  удерживаемой custom-клавиши; смена конфигурации сбрасывает последовательность.

## Risks / Trade-offs

- Carbon не обнаруживает все локальные shortcuts → предупреждение в настройках.
- macOS может перехватить системную комбинацию раньше → отказ известных системных комбинаций
  и проверка регистрации; не обещаем полный перечень конфликтов.
- Глобальная регистрация резервирует custom shortcut и в исключённых приложениях,
  но конвертация там запрещена; UI объясняет глобальную область действия.

## Migration Plan

Нет новой настройки → двойной Shift. Повреждённая настройка → двойной Shift.
Настройка не включает новый recovery runtime. Обычная установленная сборка заменяется
только после проверок; тестовые сборки создаются отдельно.
