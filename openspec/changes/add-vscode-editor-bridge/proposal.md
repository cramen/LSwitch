## Why

Обычный профиль VS Code в сборке 489 добавил `ghbdtn` после `привет` вместо замены:
AX-отражение выделения не подтвердило состояние реальной модели редактора.
Отказ `unverifiedEditorModel` в 503 предотвращает повторение, но рабочая поддержка
VS Code и исправление его комментариев/строк остаются незавершёнными.

**Статус осуществимости на 2026-10-15: BLOCKED для пути `TextEditor.edit`
в установленном VS Code 1.134.0 по G3.** Сверка локальных API/JS с SHA-256 и byte
offsets показала: уже отправленная замена может примениться после срока native hold,
поскольку получатель не проверяет deadline и не предоставляет окончательную отмену.
[Контрпример и воспроизводимые основания](design.md#точная-цепочка-и-контрпример-g3)
сохранены в change. Это отрицательный результат конкретного пути, не доказательство
невозможности всех будущих bridge. G1–G4 и hold ≤400 мс не ослабляются.

## What Changes

- До реализации получить новый доказанный контракт получателя, исключающий позднюю
  запись после окончательной отмены/истечения срока в точке применения. Keybinding,
  prepare handshake, Promise timeout или отключение socket этого не обеспечивают.
  Пока такой контракт отсутствует, implementation-задачи не выполняются, D13 сохраняется.
- После прохождения проверки осуществимости добавить локальное companion-расширение VS Code и ограниченный протокол связи
  с LSwitch: снимок только активного проверенного текстового документа, одна условная
  замена точного диапазона в модели и подтверждённый результат.
- Связать запрос с исходными приложением, окном, сессией расширения, экземпляром
  документа, URI, версией, текстом диапазона и направленным выделением. Отдельно
  доказать фокус текстового редактора и предел отмены перед применением изменения.
- Сначала принять ручной протокол. Автоматика допускается только после самостоятельной
  проверки фокуса, продолжения ввода и полного ограниченного языкового контекста;
  код защищается, подтверждённые комментарии и строки исправляются.
- Сохранить native-управление TIS, удержанием ввода и точным receipt undo в LSwitch.
  Потерянное подтверждение не вызывает повторную запись или переключение на иной движок.
- Подготовить проверяемый VSIX, описание разрешений и удаления. Установка и запуск
  расширения требуют отдельного явного разрешения пользователя после подготовки пакета.
  Workspace Trust и существующие настройки безопасности не изменяются скрытно.
- Сохранить default-отказ для неподтверждённых конфигураций. Наличие bridge, зелёные
  unit-тесты или безопасный отказ сами по себе не означают принятую поддержку VS Code.

## Capabilities

### New Capabilities

- `vscode-editor-bridge`: локальная аутентифицированная связь с моделью VS Code,
  привязка к контексту и фокусу, условная замена, точный откат, защита кода и приёмка.

### Modified Capabilities

Нет. Действующие требования `safe-conversion` сохраняются. Этот change — зависимость
P0 для открытой `stage0-spikes` 3.3 / D13 и проверки комментариев/строк в
`stage2-autoswitch` 4.3; он не заменяет и не закрывает эти задачи. Связи в артефактах
этапов уточняются отдельно, без перезаписи их истории и критериев.

## Impact

Будущие области реализации: отдельный TypeScript-пакет расширения, чистый протокол
и тесты с обеих сторон, native-адаптер конвертации/контекста, интеграция receipt undo,
сборка VSIX и документация установки/приёмки. Новый транспорт — локальный Unix socket
в личном каталоге; сетевые службы, файловые команды и произвольное выполнение исключены.

Первая целевая конфигурация: установленный desktop VS Code 1.134.0
(`com.microsoft.VSCode`) на macOS, локальный обычный документ и одна каретка/одно
выделение. Remote, web, notebook, diff, custom editor и неподтверждённые режимы
остаются явными отказами. На этапе предложения создан только план; поддержки ещё нет.
Новый API/receiver contract потребует отдельной source-сверки и уточнения этих
артефактов до возобновления реализации; отрицательный G3 не засчитывается как feature PASS.
