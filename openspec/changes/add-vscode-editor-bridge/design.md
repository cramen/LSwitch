### Основания API и предел исследования

Доступен [публичный контракт тега 1.134.0](https://raw.githubusercontent.com/microsoft/vscode/1.134.0/src/vscode-dts/vscode.d.ts):
`TextDocument` предоставляет URI, languageId, версию, текст и UTF-16 координаты;
повторное открытие создаёт другой объект. `TextEditor.edit` строит условное изменение
документа, возвращая асинхронный результат. Это не обещание атомарного сравнения
фокуса или selection. `activeTextEditor` может сохранять последнее редактируемое
поле; `WindowState.focused` относится к окну. `registerTextEditorCommand` допускает
прямой вызов и требует активного редактора, а не доказанного фокуса его текста.

Первоначальное чтение [extHostTextEditor.ts ветки main](https://raw.githubusercontent.com/microsoft/vscode/main/src/vs/workbench/api/common/extHostTextEditor.ts)
и [mainThreadEditor.ts ветки main](https://raw.githubusercontent.com/microsoft/vscode/main/src/vs/workbench/api/browser/mainThreadEditor.ts)
показало version guard перед `executeEdits`. Эти удалённые implementation-файлы
по установленному commit/тегу получить не удалось (cache miss); равенство main
установленному коду не предполагается. Позднее цепочка проверена непосредственно
в поставляемом JS установленной 1.134.0, с хэшами и byte offsets ниже.
Она подтверждает version guard, но не атомарный focus/selection CAS или отмену
уже отправленной операции. Для G3 получен конкретный статический контрпример.

[Контексты when](https://code.visualstudio.com/api/references/when-clause-contexts)
различают `editorTextFocus`, `editorFocus`, `inputFocus` и `terminalFocus`.
Они полезны для маршрутизации клавиши; условие keybinding не аутентифицирует
источник команды и не связывает последующий асинхронный edit с прежним фокусом.
[Документация размещения расширений](https://code.visualstudio.com/api/advanced-topics/remote-extensions)
различает локальный UI host и workspace host, который может быть удалённым.
Первый профиль намеренно ограничен локальной desktop-конфигурацией.

Статический контрпример при неизменных G1/G2/G4:

1. Документ имеет V. Native начинает hold, extension отправляет edit с V.
2. RPC уже стоит в очереди renderer; обработка задерживается дольше 400 мс.
3. Native deadline истекает, sender отменяет своё ожидание/socket-запрос и
   выпускает hold. Это не удаляет уже поставленный `$tryApplyEdits`.
4. Renderer обрабатывает edit до следующего изменения текста. Модель всё ещё V,
   editor существует: запись выполняется после release.

Этот порядок разрешён исследованным кодом; он не требует ошибки VS Code или
фактической смены фокуса. Следующая клавиша иногда может изменить V раньше RPC,
но такого порядка между очередями не гарантировано; без неё V вообще не меняется.
Это **source-контрпример, не воспроизведённый live-тест**.

| Файл | Offset | Проверяемое действие |
| --- | ---: | --- |
| `workbench.desktop.main.js` | 4349136 | Contributed command направляется в `$executeContributedCommand` |
| `extensionHostProcess.js` | 1154862 | Handler contributed command выполняется в extension host |
| `extensionHostProcess.js` | 2023637 | `registerTextEditorCommand` получает active editor и вызывает тот же `TextEditor.edit` |

`editorTextFocus`/when ограничивают dispatch, но не превращают callback в renderer
commit и не передают deadline/cancel. Прямой вызов команды также возможен.
RU/EN-конфликты назначений и multiwindow-матрица этим source review не проверены.

Promise.race/AbortController вокруг Promise, закрытие socket, deregister команды,
prepare handshake или перезапуск host не доказывают отмену уже переданного RPC.
Компенсирующий edit/Cmd+Z и искусственное изменение версии запрещены прежним
контрактом. `unknown` и отказ от retry предотвращают второй edit, но не поздний
первый; status-read может задержаться и не обеспечивает bounded release.

Для возобновления реализации нужен новый доказанный **контракт получателя**:
окончательный cancel/commit fence либо проверяемое истечение запроса в самой точке
применения с согласованным сроком, совместимые с hold ≤400 мс. После этого отдельно
доказываются неизменные G1/G2/G4. Такой контракт у исследованного пути не найден.
Вывод не распространяется на все будущие bridge/API и не разрешает ослабление gates.

## Goals / Non-Goals

**Goals:**

- Заменять точный диапазон проверенной модели один раз, без предварительного
  изменения selection, Paste, Unicode-пакета или Cmd+Z.
- Сделать модель состояния, отказа и неизвестного результата проверяемой чистыми
  тестами и управляемыми гонками до живого включения.
- Разделить приёмку manual и auto; сохранить исходные пределы удержания и задержки.
- Ограничить доступ текущим подтверждённым буфером и парой связанных процессов.

**Non-Goals:**

- Автономный доступ расширения к файловой системе workspace, обход Trust, сетевой
  сервис, remote/web, notebook/diff/custom editor, несколько кареток и IME без приёмки.
- Private API VS Code, патч установленного редактора или доверие к DOM/AX proxy.
- Изменение существующих требований безопасности ради удобства публичного API.
- Объявление другого Electron-редактора поддержанным на основании VS Code.

## Decisions

### D1. Сначала проверка осуществимости, затем ручной протокол

До разрешения реальной записи обязательны доказательства G1–G4:

| Gate | Что нужно доказать | Недостаточное основание |
| --- | --- | --- |
| G1: принадлежность | Связь native PID/окна с конкретной локальной сессией и экземпляром редактора | PID, заголовок, URI или self-reported window nonce по отдельности |
| G2: фокус | Проверка фактического текстового фокуса и selection относится к той же точке применения | `activeTextEditor`, `window.focused`, успешный keybinding, post-read |
| G3: срок | Отмена до записи окончательна; уже отправленный edit не может записать после отмены и освобождения hold | Timeout Promise, закрытие socket, последующий status |
| G4: каретка | Одна модельная операция даёт требуемую каретку и точный обратный edit | Отдельный selection setter, Cmd+Z, скрытая компенсирующая операция |

Исследованный `TextEditor.edit` 1.134.0 **не удовлетворяет G3** по контрпримеру выше.
G1/G2/G4 остаются недоказанными и не ослабляются. До нового receiver contract и
обновления этих артефактов implementation-задачи разделов 2–7 не выполняются:
не создаются transport/extension/VSIX и не отправляются production edits.
Сохраняется D13. Разрешено дальнейшее read-only исследование осуществимости;
серия быстрых успехов или один будущий live replay не отменяет source-контрпример.
Это техническая блокировка конкретного пути, а не ожидающее разрешение пользователя.

### D2. Companion extension и native-владелец транзакции

Разделы D2–D8 — условный будущий план после снятия G3 по D1, не разрешение начать реализацию.

Планируемый пакет `extensions/vscode` содержит TypeScript-протокол, адаптер публичной
модели и тесты; native-часть добавляет заменяемый адаптер к существующей транзакции
LSwitch. Расширение не управляет TIS, clipboard, глобальными клавишами, обучением
или звуком. Native-код выполняет TIS/NSWorkspace только на main thread.

Поддержанный профиль выбирается по exact bundle, принятой версии протокола и
связанной сессии; при отсутствии любого допуска сохраняется `unverifiedEditorModel`.
Никакой AX/clipboard/keyboard fallback после входа в bridge не разрешён. Рабочий
manual допускается отдельно; auto продолжает отказывать до раздела D8 и полной приёмки.

Альтернатива «выделить через AX, затем вставить» отвергнута по реальному дефекту.
Универсальный Unicode ввод также не подтверждает selection модели и не заменяет bridge.

### D3. Локальный канал, связывание и минимальный доступ

Native-процесс создаёт отдельный короткий runtime-каталог текущего пользователя
вне репозитория с правами `0700`; Unix socket получает `0600`, создание начинается
под `umask 077`. Имя не берётся из workspace. Перед соединением/удалением проверяются
владелец, тип объекта, отсутствие symlink и принадлежность текущему экземпляру.
Старый или чужой socket не удаляется по одному совпадению пути.

Связывание явное, с новым случайным session nonce и взаимной проверкой challenge.
Секрет хранится в личном защищённом хранилище/памяти, вне repo, логов, workspace
settings, синхронизации и аргументов процесса; выбранный способ и его отзыв входят
в review VSIX. Проверка local peer UID и nonce обязательна. Одинаковый UID сам по
себе не доказывает подлинность; расширения одного extension host не изолированы
этим протоколом. Не обещается защита от уже скомпрометированного пользователя/host.

Протокол содержит фиксированные типы: handshake, подготовка, снимок, одна условная
замена, cancel, read-only status и результат. Клиент не передаёт произвольную команду,
исполняемый путь или URI для открытия. URI служит только точным сравнением уже
захваченной модели. Нет `openTextDocument`, `showTextDocument`, shell, файловых
операций над документами или сетевого listener как возможностей IPC.

Начальные лимиты: один активный запрос на native-транзакцию и сессию; один буфер
до 16 384 UTF-16 units; один диапазон до 256 graphemes; frame до 128 KiB; неизвестные
поля/версии, неверные длины и диапазоны отвергаются. Чтение размера предваряет
выделение памяти и текстовый payload. Идентификаторы, сроки, счётчики replay и
число записей журнала состояний ограничены. Текст/URI остаются в RAM только на
время запроса/receipt; диагностика содержит категории, длительности и размеры.

### D4. Происхождение модели и ограниченный снимок

Идентичность составная: native process generation и actual window identity,
случайная session generation расширения, локальные токены экземпляров `TextEditor`
и `TextDocument`, точный URI, версия, languageId и направленное selection
`anchor/active`. URI и номер версии не заменяют экземпляр: закрытие/повторное
открытие, reload host, split editor и два окна с одним URI инвалидируют старые токены.

Публичный API не предоставляет готового доказанного отображения extension session
в native window identity. G1 должен проверить явное связывание через текущую
нативную цель и команду данного окна; неподтверждённые окна не получают payload.
Имя окна, `viewColumn`, env sessionId и process ID не объявляются этим отображением.

Снимок разрешается только после допуска текущего текстового фокуса. Он снимается
без асинхронной паузы между чтением identity/version/selection и текста; после
чтения повторно сверяются метаданные. UTF-16 offset/position должны обратимо
совпадать; автоматическое `validateRange`-обрезание не принимается. Снимок полного
буфера не пересобирается из AX-фрагментов или соседних вкладок. При превышении
лимита первая версия явно отказывает и manual, и auto, сохраняя простую доказуемую границу.

### D5. Проверенный native editor-command кандидат не устраняет G3

Кандидат: зарегистрированная команда редактора и локальная keybinding с
`editorTextFocus` и отрицательными контекстами неподдержанных режимов. Конкретная
клавиша **не выбрана**: F13 — только возможный пример, не безопасный default.
Перед выбором проверяются встроенные/пользовательские назначения, раскладки,
оборудование, конкурирующие расширения и последствия недоставленной команды.

Native LSwitch удерживает ввод в пределах существующего бюджета и подготавливает
аутентифицированный запрос. Предварительный вызов gate должен доказать исходное
окно/поле до снимка. После получения снимка native вычисляет преобразование и
подготавливает одноразовый pending request. Повторный локальный gate сверяет
ожидаемые session/editor/document/URI/version/range/selection/original/deadline;
при совпадении синхронный callback строит ровно один `replace` точного `Range`.
Между финальной сверкой и созданием builder нет `await` и повторного поиска цели.

Этот кандидат **не проходит G3**: установленный handler возвращается в ту же
очередь edit RPC, см. offsets выше. Он не является готовым решением гонки.
Возможны смена фокуса
между dispatch keybinding и callback, запоздавшие события selection и смена фокуса
после callback, пока RPC идёт к модели. Прямой вызов команды обходит `when`;
`registerTextEditorCommand` не выдаёт доказательство происхождения вызова.
Pending nonce защищает протокол от случайного вызова, но сам не доказывает UI-фокус.
G2 требует отдельного доказательства этих промежутков, включая поиск, Quick Open,
find/replace, terminal, debug REPL, webview, rename, suggestion/snippet и переключение окон.
Результат «ни разу не воспроизвелось» без контракта недостаточен.

### D6. Точка применения, отмена и неоднозначность

Для модельной записи точка линеаризации — принятие единственного edit реальной
моделью после проверок, а не получение IPC, запуск command callback, отправка RPC
или ACK. В установленной 1.134.0 это участок `applyEdits` перед `executeEdits`
в `workbench.desktop.main.js`, byte offset 4443822.
Гарантия версии защищает от изменения текста; изменение только selection/focus
может не менять версию. Описанная source-проверка не даёт атомарного focus CAS.
Требование отмены при таком изменении сохраняется; это открытое обязательство G2.

Машина состояний:

| Состояние | Допустимое продолжение |
| --- | --- |
| prepared | Проверить gate и отправить единственный edit либо окончательно отменить |
| submitted | Только дождаться результата, проверить тот же requestID или зафиксировать unknown |
| committed | Прочитать и подтвердить результат; создать receipt только при полном совпадении |
| rejected/cancelled | Terminal; повторная доставка возвращает то же состояние без записи |
| unknown | Запрет новых edit/undo этой транзакции; только ограниченная сверка статуса |

Одинаковый requestID с другим payload отклоняется. Повтор идентичного запроса
возвращает сохранённое состояние, никогда не повторяет edit. После restart session
старые запросы не принимаются; отсутствие старого журнала означает unknown, а не
разрешение повторить. Терминальные записи ограничены по объёму и времени, а
истёкший ID остаётся недопустимым в текущей session generation.

Deadline не продлевается при переподключении. Отмена в `prepared` окончательна;
после `submitted` API Promise без CancellationToken нельзя объявить отменённым
по таймеру. Нельзя одновременно обещать ≤400 мс hold и отсутствие поздней записи
без G3. Стенд обязан задержать именно участок после submission и проверить судьбу
edit после освобождения ввода. Пока решение не доказано, запрещён production submit;
ни бессрочный hold, ни ранний release с возможной поздней записью не принимаются.
Для текущего пути невозможность доказать G3 уже показана source-контрпримером.
Описанные состояния остаются требованиями будущего receiver contract; они не
разрешают реализовать sender-only unknown/release как обход блокировки.

### D7. Одна замена, receipt и каретка

Редактор получает только точные original/replacement/range для единственной
операции. Selection setter не используется до/после edit. Будущая реализация
проверяет, что естественная трансформация selection даёт требуемую каретку;
случай, требующий второй операции, остаётся неподдержанным. G4 отдельно проверяет
caret, прямое/обратное пользовательское выделение, начало/середину/конец и undo.

После ответа проверяются версия модели, весь ограниченный ожидаемый буфер,
selection и принадлежность цели. `true` от API без readback не даёт `converted`.
При неизвестном результате нет повторного edit, смены движка, нового receipt,
звука/обучения или слепого переключения TIS. При подтверждённом изменении и отдельном
отказе TIS сохраняется честный частичный статус; текст не переписывается повторно.

Native receipt хранит оригинал, результат, диапазон, разделитель, исходную/целевую
раскладку и подтверждённые идентичность/версию/каретку. Undo проходит те же gates
и отдельным одноразовым запросом заменяет результат сохранённым оригиналом.
Новая версия, чужой edit, selection/focus change, host restart или timeout закрывают
право undo. Native Cmd+Z отвергнут: он может объединить чужие изменения с собственными.

### D8. Автоматика и кодовый контекст — отдельный допуск

После manual-приёмки расширение передаёт полный ограниченный буфер и languageId
в существующую чистую проверенную лексическую политику LSwitch. Маппинг languageId
явный; неизвестный язык, сложные raw/interpolation/regex/preprocessing-конструкции
дают unknown. Поддержка языка не выводится из расширения файла или подсветки темы.
Требование пользователя сохраняется: код не исправлять, комментарии и строки
исправлять только при доказанном контексте всего слова. Manual обходит только lexer.

Для auto повторяются G1–G4 при приходе разделителя, проверяется источник кандидата,
сохранение точного separator, продолжение из очереди, receipt undo и обучение.
Отдельно измеряются cold/repeat обеих раскладок от исходного события до подтверждённого
результата; цель ≤200 мс и предел callback остаются исходными. IPC/lexer не исполняются
в hot callback. Отказ при запуске и unknown не засчитываются как быстрый успех.

## Risks / Trade-offs

- [Public API не обеспечивает G2/G3] → проверка осуществимости имеет приоритет;
  default D13 сохраняется. Условная запись по версии решает только часть проблемы.
- [Расширения/форматтеры меняют модель] → версия и полный ожидаемый readback;
  не отключать чужие расширения в пользовательской среде для сокрытия дефекта.
- [Одинаковый URI в нескольких окнах] → instance/session/window tokens и
  отрицательные тесты; ошибка маршрутизации не исправляется выбором «похожей» вкладки.
- [ACK-loss и перезапуск] → at-most-once submission, unknown и read-only status;
  не обещать exactly-once через crash без доказательства.
- [Секрет доступен скомпрометированному host] → честная граница доверия,
  минимальные команды и отсутствие сетевого/файлового доступа через протокол.
- [Ограничение 16K/одной каретки уменьшает покрытие] → явный безопасный отказ;
  расширение поддержки требует собственной матрицы, а не ослабления проверок.

## Migration Plan

0. **BLOCKED на G3:** read-only исследовать новый receiver contract, проверить точную
   версию и обновить этот change. До такого контракта пункты 1–6 ниже не выполняются.
1. После нового контракта завершить source/API review и проверки G1–G4; подготовить стенд,
   фиксацию зависимостей, воспроизводимый VSIX и отчёт о полном содержимом пакета.
2. До установки показать пользователю версию/hash VSIX, действия связывания,
   область доступа, план изолированного тестового окна и способ полного удаления.
   Получить отдельное явное разрешение на установку и запуск подготовленного расширения.
   Текущие разрешения на CGEvent/UI-тесты этого разрешения не заменяют.
3. После разрешения использовать отдельный тестовый профиль/каталог расширений
   с собственными документами; не менять глобальные Trust, раскладку shortcuts,
   включённость остальных расширений и настройки пользовательского профиля скрытно.
4. Выполнить реальные гонки и матрицу manual; при успешных gates принять только
   конкретный профиль. Затем отдельно принять auto/код и показатели производительности.
5. Включить обычный маршрут только после всех его допусков. Для rollback выключить
   bridge и вернуть D13, закрыть свои соединения и отозвать pairing; удалить только
   собственные runtime-объекты. Не менять документы и clipboard при отключении.
6. Связать результаты с stage0 3.3 и stage2 4.3 без автоматического закрытия остальных
   приложений/языков; archive допустим после полной проверки задач этого change.
