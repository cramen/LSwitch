## Context

См. proposal.md (Why). Репозиторий содержит каркас: `LSwitchCore`
(KeystrokeBuffer, LayoutMap) и menu-bar агент без перехвата. Требования —
в `specs/keyboard-interception` и `specs/text-conversion`. Ограничения
из TZ.md: macOS 13+, Swift 6, ноль сетевых запросов, hot path ≤ 1 мс,
буфер последних символов ≤ 256 в памяти.

Спайкам нужна среда запуска с реальными разрешениями TCC — поэтому весь
экспериментальный код живёт внутри существующего menu-bar агента и
управляется из его меню (пункты «Спайк: …»), а не выносится в отдельные
утилиты: подписанный/запущенный от пользователя процесс с стабильным
bundle-путём — единственный способ получить осмысленный ответ TCC.

## Goals / Non-Goals

**Goals:**

- Получить воспроизводимые ответы на P0.1–P0.3 (TZ.md §5) с кодом,
  который при успехе переиспользуется в этапе 1 без переписывания.
- Закрыть ADR-001 (App Sandbox и дистрибуция) фактами, а не предположениями.
- Сделать `swift test` рабочим локально и в CI.

**Non-Goals:**

- Продуктовая логика MVP: хоткеи, откат, настройки, PermGuard, blacklist UI.
  Спайки включаются вручную из меню и не обязаны быть удобными.
- Классификатор/автопереключение (этап 2).
- Полировка: обработка всех edge-кейсов оставляется этапу 1; спайк
  фиксирует «работает / не работает / условия».

## Decisions

### D1. Event tap: session-level listen-only, обработка в отдельной очереди

`CGEvent.tapCreate(tap: .cgSessionEventTap, place: .headInsertEventTap,
options: .listenOnly)`. Callback только копирует событие в lock-free
кольцевой буфер и возвращается; разбор — на выделенном `DispatchQueue`.
Это прямое следствие требования ≤ 1 мс в hot path и митигация
`kCGEventTapDisabledByTimeout`.

Альтернатива: `NSEvent.addGlobalMonitorForEvents` — отклонена: не видит
события в secure-контекстах и не даёт меток источника; оставляем как
запасной вариант для этапа 1, если event tap покажет нестабильность.

### D2. Метка собственных событий — `CGEventSource(userData:)`

Синтезированные события создаются с `CGEventSource`, в котором записан
магический 64-битный маркер; в callback события сравниваются по
`CGEventSourceStateID`/`userData` источника. Альтернатива — сравнение по
`kCGEventSourceUnixProcessID` собственного PID — отклонена: PID переиспользуется
и не различает источники внутри одного процесса. Спайк P0.1 обязан
экспериментально подтвердить, что маркер доезжает до callback (документировано
плохо — это один из вопросов к спайку).

### D3. Восстановление tap — пересоздание, а не re-enable

На `kCGEventTapDisabledByTimeout` / `kCGEventTapDisabledByUserInput` tap
уничтожается и создаётся заново (плюс `CGEvent.tapEnable` как быстрый путь).
Наблюдения за sleep/wake и Fast User Switching — через
`NSWorkspace` нотификации с принудительной проверкой живости tap.
Критерий P0.1: 8 часов стабильного перехвата включая sleep/wake.

### D4. Конвертация: AX-first с per-app кэшем режима

Порядок попыток: (1) `AXSelectedText` → запись обратно через
`AXUIElementSetAttributeValue`; (2) если недоступно — чтение
`AXValue` поля с вычислением границ последнего слова; (3) clipboard-fallback.
Результат («приложение X — режим Y») кэшируется в памяти по bundle ID;
персистентность — этап 1.

Матрица проверки P0.2: TextEdit, Safari, Chrome, Telegram, VS Code.
Критерий: AX-режим работает минимум в 3 из 5.

### D5. Clipboard-fallback: снимок всех pasteboard items + хэши

Перед Cmd+C снимаются все `NSPasteboardItem` со всеми типами (включая
файловые промисы — копируются данные, не ссылки), после Cmd+V буфер
восстанавливается записью снимка. Инвариант проверяется хэшами
(SHA-256 по `type + data`) до/после. Паузы: базовые 20–50 мс, экспоненциальный
рост при неуспехе (детект — сравнение changeCount/данных), максимум
3 повтора. Критерий P0.3: буфер бит-в-бит идентичен.

Открытый подвопрос для спайка: приложения, читающие буфер лениво
(pasteboard promises), — проверить, что восстановленный буфер ими
принимается.

### D6. Проверка sandbox — две сборки одного кода

Для ADR-001 собираем спайки дважды: с App Sandbox (+ temporary exceptions)
и без. Критерий: если event tap и AX-запись работают из-под sandbox без
temporary exceptions — ADR-001 фиксирует sandbox + MAS-совместимость;
иначе — дистрибуция вне MAS (Developer ID + notarization), как у
Rectangle/Keyboop. Решение записывается в `docs/adr/ADR-001-app-sandbox.md`.

### D7. Тестовое окружение

`swift test` падает, потому что `xcode-select` указывает на Command Line
Tools (без XCTest). Локально: переключить на `/Applications/Xcode.app`.
В CI (GitHub Actions): использовать `macos` runner с полным Xcode и
`xcode-select` в workflow — заодно это подготовка к CI из P0.5.

## Risks / Trade-offs

- [Маркер собственных событий не доезжает до callback (недокументированное поведение)] → в спайке P0.1 предусмотрен план B: подавление по временному окну + сравнению с очередью синтезированных событий.
- [AX-режим работает менее чем в 3 из 5 приложений] → не блокер: clipboard-fallback обязателен в любом случае; результат меняет только приоритет режимов и ожидания матрицы 6.2.
- [Спайки требуют ручной выдачи разрешений TCC и 8-часового прогона] → критерии верификации оформляются чек-листами в tasks.md; автоматизируется только наблюдаемое (логирование событий tap).
- [Sandbox-сборка потребует temporary exceptions, которые Apple может не одобрить в MAS] → именно это и измеряет D6; при сомнениях ADR-001 фиксирует дистрибуцию вне MAS — потеря MAS принята заранее (TZ.md, R1).
- [Спайковый код в menu-bar агенте раздует каркас] → весь экспериментальный код изолируется в `Sources/LSwitchCore` за протоколами; пункты меню спайков помечаются и удаляются/заменяются в этапе 1.

## Open Questions

- Принимают ли приложения с ленивым чтением буфера (promises) восстановленный снимок pasteboard — выяснится в P0.3, влияет только на детали D5.
- Точное поведение `userData` у `CGEventSource` на macOS 13–15 — выяснится в P0.1, есть план B (см. риски).
